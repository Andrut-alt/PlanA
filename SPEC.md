# PlanA Bot — специфікація

Особистий Telegram-бот для щоденних звичок, задач плану, цілей і серії днів.
Один користувач (власник). Живе на AWS Lambda, дані в DynamoDB, нагадування через EventBridge Scheduler.

> Після кожного кроку зупинись і покажи, як перевірити результат. Пиши простий, читабельний код:
> без фреймворків для бота, без зайвих абстракцій. Коментарі англійською, тексти бота українською.

## 1. Що робить бот

### Команди
| Команда | Що робить |
|---|---|
| `/start` | Привітання + список команд |
| `/today` | План на сьогодні: задачі (включно з простроченими невиконаними) і звички. Кожен пункт — inline-кнопка `⬜ назва` / `✅ назва`. Натискання перемикає стан і **редагує це ж повідомлення** (без нових повідомлень). Вгорі: дата, серія 🔥, «мінімум дня» |
| `/yesterday` | Те саме для вчора (щоб відмітити заднім числом) |
| `/week` | Підсумок поточного тижня: активні дні X/7, що виконано по сферах, серія, карта активності |
| `/streak` | Серія, найкраща серія, карта активності за 12 тижнів |
| `/goals` | Цілі, згруповані за горизонтом, з прогрес-баром `▓▓▓░░░░░░░ 30%` (виконані задачі цілі / усі задачі цілі) |
| `/add <дата> <назва>` | Швидко додати задачу. `<дата>` = `today`, `tomorrow` або `YYYY-MM-DD`. Сфера за замовчуванням «Інженер» |
| `/import` | Після команди бот чекає JSON-файл (документом). Замінює habits/tasks/goals/minimums. **Історію днів не чіпає** |
| `/export` | Надсилає JSON з усіма даними (бекап) |

### Нотатка дня
У вечірньому нагадуванні (21:00) бот питає: «Що ти сьогодні зрозумів? Відповідай одним реченням».
Наступне звичайне текстове повідомлення (не команда) зберігається як нотатка цього дня → відповідь «Записав ✍️».

### Нагадування (час Києва, `Europe/Kyiv`)
| Коли | Умова | Повідомлення |
|---|---|---|
| Щодня 09:00 | завжди | «Доброго ранку. Сьогодні: …» — задачі дня + мінімум + серія + кнопка-клавіатура як у `/today` |
| Щодня 21:00 | день порожній | «Сьогодні ще нічого. Мінімум: …» + клавіатура `/today` |
| Щодня 21:00 | завжди (після попереднього, якщо було) | Питання про нотатку дня |
| Щодня 23:00 | **вчора пропуск і сьогодні порожньо** | 🚨 «Вчора пропуск. Якщо сьогодні нічого — серія згорить опівночі. Мінімум: …» |
| Неділя 20:00 | завжди | Тижневий звіт = `/week` + нотатки тижня списком |

## 2. Правила і логіка (все це — чисті функції в `core.py`, покриті тестами)

- **Активний день** — у дні виконано хоча б 1 пункт (задача або звичка).
- **Серія з правилом «ніколи двічі»**: рахуємо назад від сьогодні. Активний день +1 до серії. Один пропуск серію **не рве**. Два пропуски поспіль — серія обірвана. Сьогоднішній день ще «відкритий»: якщо сьогодні порожньо, це ще не пропуск.
  - приклад: `✅✅⬜✅✅` (сьогодні останній) → серія 4
  - приклад: `✅✅⬜⬜✅` → серія 1
  - приклад: `✅✅✅⬜ + сьогодні порожньо` → серія 3 (вчора пропуск, сьогодні ще можна врятувати)
- **Найкраща серія** — максимум за всю історію з тим самим правилом.
- **Прострочені задачі**: задачі з датою < сьогодні, які не виконані в жодному дні, показуються в `/today` з позначкою `⏳ з Пн 24.11`.
- **Задача виконана** — її id є у `done` будь-якого дня. Виконання записується в день, коли натиснули кнопку. Повторне натискання знімає відмітку з того дня, де вона стоїть.
- **Карта активності** (емодзі): рядки Пн–Нд, стовпці — тижні (останні 12). `⬜` 0 пунктів, `🟨` 1–2 (мінімум), `🟩` 3+, `▫️` майбутнє або до старту. Над сіткою — підпис місяців.
- **Старт історії**: `START_DATE = 2026-11-23`.
- Усі дати рахуються в `Europe/Kyiv` (`zoneinfo`), формат ключа `YYYY-MM-DD`.

## 3. Дані

### DynamoDB, одна таблиця `planabot` (on-demand)
`PK = "USER#<chat_id>"`, `SK` — тип запису:

| SK | Поля |
|---|---|
| `HABIT#<id>` | title, area, xp, order |
| `TASK#<id>` | date, title, area, goal, xp, min, milestone |
| `GOAL#<id>` | title, area, horizon, deadline, criterion |
| `MIN#<YYYY-MM-DD>` | text |
| `DAY#<YYYY-MM-DD>` | done (list of `"t:<id>"` / `"h:<id>"`), note |
| `STATE` | awaiting_note_for (дата або null), awaiting_import (bool) |

Даних мало (сотні записів), тому для кожного запиту читати все через один `Query` по `PK` — нормально і просто.

### Формат `plan.json` (для `/import`)
```json
{
  "habits":   [{"id": "h1", "title": "...", "area": "Інженер", "xp": 10}],
  "goals":    [{"id": "g1", "title": "...", "area": "Інженер", "horizon": "Грудень", "deadline": "2026-12-07", "criterion": "..."}],
  "tasks":    [{"id": "t1", "date": "2026-11-23", "title": "...", "area": "Інженер", "goal": "g1", "xp": 10, "min": 60, "milestone": false}],
  "minimums": {"2026-11-23": "20 хв сценарних питань"},
  "rewards":  [{"id": "r1", "title": "...", "cost": 40}]
}
```
У версії 1 поле `rewards` при імпорті просто ігнорується (знадобиться у версії 2).
Сфери: `Інженер`, `Англійська`, `Тіло`, `Розум`, `Життя`. Горизонти: `Грудень`, `3 міс`, `6 міс`, `12 міс`.

## 4. Архітектура

```
Telegram ──webhook──► Lambda Function URL ──► webhook_handler ──► DynamoDB
EventBridge Scheduler (4 розклади, Europe/Kyiv) ──► scheduler_handler ──► Telegram sendMessage
```

- **Python 3.12**, без бот-фреймворків: Telegram Bot API через `urllib.request` (жодних залежностей → простий деплой). `boto3` вже є в Lambda.
- **Webhook**: Lambda Function URL (`AuthType: NONE`) + перевірка заголовка `X-Telegram-Bot-Api-Secret-Token` (секрет задається в `setWebhook`). Без правильного секрету → 403.
- **Маршрутизація за шляхом (закладаємо одразу під версію 2)**: `webhook_handler` дивиться на `rawPath` з події Function URL. `POST /webhook` → оновлення від Telegram (webhook ставимо саме на `<FunctionURL>/webhook`). Шляхи `/api/*` у версії 1 повертають 404, у версії 2 там буде API для Mini App. Тому вся логіка «відмітити пункт», «зберегти нотатку», «зібрати стан дня» має жити у функціях `repo.py` / `core.py`, а не всередині обробників Telegram, щоб API потім просто викликало ті самі функції.
- **Доступ**: обробляти тільки оновлення від `OWNER_CHAT_ID`, усе інше ігнорувати мовчки.
- **Розклади**: SAM-подія `ScheduleV2` з `ScheduleExpressionTimezone: Europe/Kyiv`, у `Input` передається `{"kind": "morning" | "evening" | "late" | "weekly"}`.
- **Секрети**: `BOT_TOKEN`, `WEBHOOK_SECRET`, `OWNER_CHAT_ID` — параметри SAM (`NoEcho: true`) → змінні середовища Lambda. Не комітити в git.
- **Регіон**: `eu-central-1` (Франкфурт).
- **Callback data** кнопок: `x:<YYYY-MM-DD>:<t|h>:<id>` (≤ 64 байти). Після обробки завжди `answerCallbackQuery`.

### Структура репозиторію
```
planabot/

  samconfig.toml         # створиться після sam deploy --guided
```

## 7. Версія 2: Telegram Mini App

Починати **тільки після того, як версія 1 поживе 1–2 тижні**. Бот лишається для нагадувань і швидких ✅, а Mini App стає «вікном» з повною картиною.

### Що показує Mini App
Те саме, що дашборд PlanA (`webapp/dashboard_reference.html` — готовий дизайн, береться за основу):
- шапка: серія 🔥, XP за сьогодні, загальний рівень, монети;
- карта активності як на GitHub (зелені клітинки, з дати старту і до літа);
- день: задачі плану + звички великими картками (натиснув на картку → виконано), «мінімум дня», поле нотатки; стрілки між днями;
- сфери (Інженер, Англійська, Тіло, Розум) з рівнями і прогрес-барами;
- нагороди за монети (1 XP = 1 монета);
- цілі з прогресом.

### Як відкривається
- Кнопка меню чату: `setChatMenuButton` з `{"type": "web_app", "text": "PlanA", "web_app": {"url": "<URL сторінки>"}}`.
- Плюс команда `/app` → повідомлення з inline-кнопкою `web_app`.
- Сторінка підключає `https://telegram.org/js/telegram-web-app.js`, викликає `Telegram.WebApp.ready()` і `Telegram.WebApp.expand()`, кольори бере з `Telegram.WebApp.themeParams` (CSS-змінні `--tg-theme-*`), з fallback на власну палітру.

### Хостинг фронтенду
Статичні файли (`webapp/index.html`) на HTTPS. Найпростіше: **GitHub Pages**. Альтернатива в AWS: S3 + CloudFront (додати в `template.yaml`). URL сторінки — у змінну `WEBAPP_URL`.

### API (та сама Lambda, шляхи `/api/*`)
| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `GET /api/state` | — | `{today, habits, tasks, goals, minimums, rewards, days, purchases}` (усе для рендеру; розрахунки серії/XP можна робити на фронті, як у дашборді, або віддавати готовими) |
| `POST /api/toggle` | `{date, kind: "t"|"h", id}` | оновлений день |
| `POST /api/noai` | `{date, id}` | оновлений день (бонус +5 XP за задачу без AI) |
| `POST /api/note` | `{date, text}` | `{ok: true}` |
| `POST /api/buy` | `{reward_id}` | оновлений список покупок (перевірити баланс на бекенді) |

- CORS: дозволити тільки origin сторінки Mini App (`WEBAPP_ORIGIN`), методи `GET, POST, OPTIONS`, заголовок `Authorization`, `Content-Type`.
- Нові дані в DynamoDB: `REWARD#<id>` {title, cost}, `PURCHASE#<timestamp>` {reward_id, title, cost, date}. `plan.json` отримує поле `rewards`.
- Бот і Mini App пишуть в одні й ті самі записи `DAY#…`, тому відмітка в чаті одразу видна в Mini App і навпаки.

### Безпека — обов'язково (не пропускати при вайбкодингу)
Фронтенд надсилає в кожному запиті заголовок `Authorization: tma <Telegram.WebApp.initData>`. Бекенд **перевіряє підпис** перед будь-якою дією:
1. Розібрати `initData` як query string. Забрати поле `hash`.
2. `data_check_string` = усі інші пари `key=value`, відсортовані за ключем, з'єднані через `\n`.
3. `secret_key = HMAC_SHA256(key=b"WebAppData", msg=BOT_TOKEN)`.
4. `expected = hex(HMAC_SHA256(key=secret_key, msg=data_check_string))`; порівняти з `hash` через `hmac.compare_digest`.
5. Перевірити, що `auth_date` не старший за 24 години.
6. Розпарсити `user` (JSON) і перевірити `user.id == OWNER_CHAT_ID`.
Будь-яка невдача → `401`, без деталей. Функцію `validate_init_data()` покрити тестами (валідний підпис, змінене поле, прострочений `auth_date`, чужий `user.id`).
